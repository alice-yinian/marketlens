# MarketLens

抓取 OKX 市场状态与你的仓位，用模板生成 AI 复盘提示词。**Windows + Android** 双端。

> 不做交易，不接 LLM。它只做一件事：**把「我现在处于什么市场状态、我当时的仓位表现如何」
> 整理成一份可以直接粘给 AI 的提示词**——然后你拿去哪家 AI 都行。

---

## 它解决什么

交易复盘最难的不是没有数据，而是**数据没和当时的处境绑在一起**。

「这笔空单亏了 500」是没用的信息。
「这笔空单是在**趋势向上 + 高波动 + 多头拥挤**的状态下开的，而我在这种状态下 6 笔亏了 5 笔」——
这才是能改的东西。

MarketLens 做的就是这件事：把每一笔仓位绑定到它**开仓时刻**的市场状态，再按状态分组统计。

---

## 三个核心设计

### 1. 隐私分级：AI 到底看到了什么，你说了算

提示词要粘到外部 AI，所以金额必须可控。**分级在后端强制生效——改模板也绕不过去。**

| 等级 | 行为 |
|---|---|
| **L0 全量** | 完整金额与数量 |
| **L1 百分比（默认）** | 金额转成占账户权益的百分比；权益只给量级区间（如 `$10k–$50k`） |
| **L2 脱敏** | 只保留方向、杠杆与市场状态，不含任何金额与数量 |

实现上不做「敏感字段清单」——那种清单**漏一个字段就是一次泄漏，而且漏了没有症状**。
改成**自描述数值**（`{kind: usd\|pct\|count\|unavailable, value}`），
凡是钱天然在射程内。同一份模板在三个等级下都能工作，只是数字换形态。

### 2. 历史仓位双源合并

官方 `positions-history` 窗口有限（约 3 个月），而复盘需要长期数据。

- **官方接口**：权威，但只有窗口内
- **本地留痕**：每次刷新写一条，长期唯一解，但只能记录首次运行之后

两者合并去重，并**如实标注每笔的来源与时间精度**（`官方` / `仅本地` / `时间精确` / `近似`）。
数据可信度是复盘结论的地基，不能糊。

### 3. 拿不到的数据必须显式声明

模板里任何缺失字段都渲染成 `[数据不可得：原因]`，**绝不留空**。

AI 看到空白会自行编造，看到明确的不可得声明才会谨慎。同理：

- 模板引用了不存在的变量 → **直接报错**，并把缺失变量**一次列全**
- 权益不可得时，L1 **拒绝退回原始金额**，降级为「不可得」

## 技术选型

| | |
|---|---|
| 应用框架 | Tauri v2（Rust 后端 + Web 前端） |
| 前端 | React 19 + TypeScript + Tailwind 4 |
| 模板引擎 | minijinja（Jinja2 风格，Rust 侧渲染） |
| 存储 | SQLite（sqlx）+ Stronghold 密钥库 |
| 图表 | lightweight-charts |

**所有业务逻辑都在 Rust 侧**，前端只是视图层。双端行为一致，模板输出逐字节相同。

---

## 快速开始

```bash
npm install
npm run tauri dev          # 开发
npm run tauri build        # 打包（产出安装包）
```

首次启动走 3 步引导：设主密码 → 录只读凭据（可跳过，仅看行情）→ 选标的集。

> **凭据必须是只读权限。** 应用不实现任何私有 POST 端点，即使密钥可交易也没有下单能力，
> 但只读仍是更安全的默认。

### 无头验证（Linux 开发机）

开发机是 RHEL 10 系容器，**X.Org 服务器已被移除**，常规截图路径全部失效。
可行组合是 weston headless + Xwayland + 自研的 X11 工具：

```bash
MARKETLENS_DEV=1 scripts/headless-smoke.sh /tmp/shot.png
MARKETLENS_BIN=src-tauri/target/release/marketlens scripts/headless-smoke.sh /tmp/shot.png
```

`tools/xshot` 提供 `xshot`（抓窗口）、`xtype`（注入键鼠）、`xtype geom`（窗口偏移）。
这些工具**不参与应用构建**，只为无头驱动而生。

## 测试

```bash
cd src-tauri && cargo test        # Rust（含数据库迁移与类型导出）
npm run test                      # 前端
cd src-tauri && cargo clippy --all-targets -- -D warnings
```

联网测试默认 `#[ignore]`（需要 `MARKETLENS_TEST_API_KEY` 等环境变量）。

CI 会额外校验 **`src/lib/types.ts` 未漂移**——它是 ts-rs 从 Rust 生成的，
前后端类型对不上会让 CI 变红。

## 文档

**`docs/DESIGN.md`** —— 设计文档，也是这个项目的完整决策记录。

它不只写「怎么做」，还写**「为什么这么做」和「踩过什么坑」**：

- 23 条架构决策及其被否方案
- 每个里程碑的**实际验收记录**（含真实数据与失败过程）
- 已知不足与未验证项——**如实列出，不粉饰**

几个值得一读的坑：

- `posSide` 在净持仓模式下恒为 `net`，真实方向在 `direction` 字段——用错会把多空单混为一谈
- 密码派生不加 `opt-level = 3` 时，单次密钥库往返要 **9 分钟**（加上后 15 秒）
- Jinja 的 `|` 比 `-` 结合更紧，`{{ a - b | dur }}` 实际是 `a - (b | dur)`
- 裸 `cargo build --release` 的产物**连 devUrl 而不是内嵌资源**，必须用 `tauri build`
